# プロダクト品質仕様書

## 目的と利用境界

このアプリケーションは、日本の世帯が月に一度、口座残高と基準日を更新し、目的別現金、NISA・iDeCo、住宅ローン、教育費、税制の前提を横断して**今月の方針を記録する**ためのWebアプリケーションである。金融機関への振替、投資商品の注文、住宅ローンの返済、税務手続きは実行しない。各画面は、外部アプリで手動実行すべき内容を具体的に表示するだけである。

| 区分 | 仕様 | 受入条件 |
|---|---|---|
| 認証 | Manus OAuthによる所有者アクセス | 未認証時はデータを表示せず、ログイン導線のみを表示する |
| 月次入力 | 実口座の残高・基準日・目的を保存する | 残高、基準日、口座名の欠損または古さを口座単位で示す |
| 意思決定 | AIの方針を採用または保留として記録する | 操作は記録のみで、金融取引を発火しない |
| 現金管理 | 目的別現金の不足と振替候補を算出する | 実口座の残高を超える金額を提示しない |
| 投資計画 | NISA・iDeCoの候補、配分、試算を提示する | 期待値・根拠・限界を明記し、利益を保証しない |
| 夫婦確認 | 残高、口座操作、方針の確認者を月単位で記録する | 本人・配偶者・二人で確認のいずれかを記録できる |
| 月次完了 | 口座更新の進捗と完了状態を月単位で記録する | 未更新口座がある場合は完了を許可せず、誤記録は対象月だけ取り消せる |

## 画面構成

| 主導線 | 画面 | 役割 | 主要な状態 |
|---|---|---|---|
| 今月の判断 | `/` | 今月の残高更新、採用・保留、振替候補、夫婦確認の起点 | 読込中、入力不足、判断準備完了、保存失敗、記録済み |
| 口座・現金 | `/accounts` | 口座台帳、目的別達成、更新状況、月次完了の管理 | 未登録、未更新、古い基準日、完了可能、記録済み、取消確認 |
| 保有・配分 | `/portfolio-audit` | 保有商品の役割、追加停止、資金配分の確認 | データなし、保有あり、教育資金優先 |
| 提案の根拠 | `/recommendation` | 今月の提案、選定理由、限界の確認 | 計算済み、現金優先、投資保留 |
| 将来の試算 | `/asset-projection` | NISA・iDeCo月額の試算と将来資産シナリオ | スライダー変更、現金安全性低下、基準・下振れ・上振れ |
| 年間の予定 | `/annual-plan` | 年間アクションと見直しトリガー | 通常、金利上昇、教育期限接近、税制確認月 |
| 家計の前提 | `/settings` | 収入・支出・教育・住宅・市場前提の編集 | 読込中、編集中、保存中、保存成功、保存失敗 |

補助画面は、根拠・制度・比較・詳細試算を閲覧する用途であり、主導線から明示的に遷移できる必要がある。対象は `/funding-plan`、`/decision-evidence`、`/ideco-universe`、`/tax-documents`、`/backtest-comparison`、`/evidence-workspace`、`/nisa-universe`、`/household-opportunity`、`/goal-timeline` である。

## Web実行環境の品質範囲

本プロジェクトはReact/ExpressによるWebアプリであり、ネイティブiOS/Androidプロジェクト、証明書、署名ビルド、配布ストア設定を持たない。そのため、ネイティブ生成・署名ビルドは**対象外**とする。代替として、モバイル幅のブラウザ、タッチ相当の操作、キーボード到達性、PWAではないWebアプリとしての認証・戻る・遷移を検証する。

## 不変条件

1. プロフィールの保存失敗時は、楽観更新した画面状態を元に戻す。
2. 実口座の残高を超える振替額を表示しない。
3. 完了記録は対象月と対象シグネチャに紐付き、入力内容の変更後に古い完了記録を有効とみなさない。
4. 現金目標が未充足の場合、投資提案は現金優先または保留として明示する。
5. すべての金融操作は外部サービスで手動実行し、アプリは注文・振替APIを呼び出さない。
6. 実世帯の収入、残高、源泉徴収票、口座名、認証情報をソースコード・ログ・公開文書へ含めない。
