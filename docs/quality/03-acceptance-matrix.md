# 画面別受入基準

## 共通基準

| 観点 | 受入基準 |
|---|---|
| 認証 | 未認証時はログイン導線だけを表示し、資産情報は表示しない |
| 操作性 | 主導線はデスクトップのサイドバーとモバイルのメニューから到達できる |
| レスポンシブ | 375px幅で横スクロール、重なり、画面外に隠れる主要ボタンがない |
| 可読性 | 日本語の本文・補足・金額・警告が背景と十分に区別できる |
| 失敗処理 | 読込中、空データ、保存失敗の状態が理解でき、誤った成功表示をしない |
| 金融境界 | 振替・買付・返済・申告を実行するボタン、または外部API呼出しがない |
| アクセシビリティ | ボタン・入力・詳細表示がキーボードで到達でき、操作目的のラベルがある |

## 画面別基準

| 画面 | 必須確認 | 合格条件 |
|---|---|---|
| 今月の判断 | 残高更新、判断の採用/保留、振替候補、夫婦確認 | 入力不足時は先に更新すべき口座を示し、記録は保存失敗時に復元される |
| 口座・現金 | 口座追加・編集・削除・保存、入力警告、月次完了・取消 | 目的別進捗、更新状況、取消対象月が明確で、残高以上の振替候補を出さない |
| 保有・配分 | 保有商品の役割と買付方針 | コア・保有・追加停止の理由と、新規資金の扱いが読める |
| 提案の根拠 | 推奨、商品比較、理由表示 | 推奨の前提・限界・見直し条件が確認できる |
| 将来の試算 | 投資額スライダー、各シナリオ | 入力変更で今月の提案と将来推移が一貫して更新される |
| 年間の予定 | 月別アクション、再判定トリガー | 実行時期・確認内容・外部で行う操作が区別される |
| 家計の前提 | 収入・支出・教育・住宅・税制の編集 | 数値の保存と再計算が一貫し、入力エラーを説明する |
| 補助画面 | 制度、比較、根拠、計画の閲覧 | 主導線から到達でき、空・読込・失敗状態が説明される |
| 404 | 存在しないURL | アプリへ戻る明確な導線がある |
